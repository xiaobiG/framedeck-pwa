# FrameDeck

FrameDeck 是一个无需上传媒体文件的本地优先 PWA 工作台。它直接通过浏览器的 File System Access API 读取用户授权的目录，支持媒体播放、文件整理、截图、A/B 剪辑、G 键快速 MP4 片段、导出队列与结构化诊断日志。

## 本地运行

不要直接使用 `file://` 打开页面。请在本仓库根目录启动静态服务器：

```bash
python3 -m http.server 8877 --bind 127.0.0.1
```

然后访问：

```text
http://127.0.0.1:8877/
```

首次完整加载后，应用外壳会缓存；首次使用剪辑功能后，FFmpeg WebAssembly 也会按需缓存，可离线再次打开。媒体文件始终保留在本机，只有用户明确授权的目录可被读取或写入。

## 浏览器大文件剪辑

MP4/M4V/MOV 视频的 G 键和 A/B 导出使用按需读取、原画质重新封装：支持 H.264/H.265 视频及 AAC 主音轨，也支持无音轨视频。无需安装本地助手或上传文件。Mediabunny 1.56.1 随应用缓存，读取源文件的索引及所需数据，输出按块直接写入目标目录，不把整个源文件或完整输出加载到内存。

快速剪辑会将起点向前、终点向后对齐关键帧，保留完整 GOP，因此实际片段可能长于所选范围；文件名、任务列表和诊断日志记录实际范围。音频使用相同时间原点，边界最多按一个 AAC 包取整。此路径保留主视频轨和主音轨，不复制字幕或其他轨道，也不承诺逐帧精确裁剪。H.265 输出能否播放仍取决于播放器支持。

其他格式保留原 FFmpeg WASM 路径及大小保护。MP4/MOV 中不支持的编码会明确报错，不会悄悄丢弃音轨或回退到整文件加载。不要通过提高 WASM 大小上限来处理大视频。

`npm test` 包含带 B 帧与 AAC 音轨的样本，以及 7 GiB 稀疏 MP4 的 64 位文件偏移测试，验证片头、中段、片尾的压缩包一致性和音画时间戳。测试样本由 FFmpeg 的 testsrc2/sine 合成，无外部媒体内容。第三方库的许可证位于 `vendor/mediabunny/LICENSE`；运行 `scripts/fetch_vendor.sh` 可按锁定版本重新复制发布资源。

## 删除磁盘源文件

播放列表每行的红色「删除」按钮，以及当前预览控制区的「删除源文件」按钮，会打开浏览器二次确认框，显示该条目的相对路径。确认意味着**永久删除本地源文件**，不只是移出播放列表，也**不会移入回收站**。取消不会申请读写权限或执行文件读写。没有删除快捷键。

确认后，应用检查父目录的 `readwrite` 权限，重新查找该文件并核对句柄身份，再调用 `removeEntry(name, { recursive: false })`；不会递归删除目录。只有磁盘删除成功才移除列表项。拒绝授权、文件被移动、占用或删除失败时保留条目，并提示重新授权或检查目录。

删除其他条目会保留当前播放与进度；删除当前条目会释放旧媒体和 Object URL，并选择下一项（末项则选择上一项）。删除最后一项后显示「当前目录没有媒体文件」，清空媒体和剪辑点、禁用需要媒体的控件。删除成功后的预览加载失败会单独提示，不会冒充磁盘删除失败。

删除、重命名、复制和目录切换/移除记录互斥，冲突操作会提示等待后重试，期间仍可切换播放项。只要导出队列有等待、加载或运行中的任务，就暂不允许删除任何源文件；这是为了覆盖从先前打开目录保留的同源导出任务。删除期间不接收新的导出任务。已保存目录旁的「×」只移除保存记录，不删除磁盘目录或文件。

并发保护覆盖本页面操作。浏览器 API 不提供「比较句柄并原子删除」接口，无法保证其他页面或外部程序在最后身份检查与删除之间替换同名文件时的原子性；请避免同时在其他程序修改该文件。

`tests/source-delete.test.mjs` 直接执行页面函数，用合成句柄验证取消、读写授权成功/拒绝/异常、文件身份变化、删除异常、当前/非当前/末项删除、重复动作、并发冲突和延迟媒体读取。浏览器验收可使用隔离上下文的 OPFS 测试文件验证实际删除与回读，但这不能替代下述本地目录原生授权流程的手工验收。

## GitHub Pages

`.github/workflows/deploy-pages.yml` 会把本仓库根目录发布到 GitHub Pages。推送到 `main` 后会自动部署，默认地址为：

```text
https://xiaobig.github.io/framedeck-pwa/
```

GitHub Pages 提供 HTTPS，满足 Service Worker、PWA 安装和 File System Access API 的安全上下文要求。推荐使用最新的 Chromium 内核桌面浏览器；Safari 和 Firefox 对目录读写 API 的支持仍有限。

每次部署前，工作流会执行 `npm test` 和 `npm run check`，校验关键媒体生命周期约束、Service Worker 应用壳清单和发布资源是否完整。

## 快捷键

| 快捷键 | 操作 |
| --- | --- |
| `F3` | 媒体专注模式 |
| `F` | 进入或退出浏览器全屏 |
| `C` | 全屏时显示或隐藏剪辑浮窗（每次进入全屏默认隐藏，退出后恢复显示） |
| `F4` | 复制到目标目录 |
| `Space` | 复制当前文件并预览下一项 |
| `[` / `]` | 设置 A/B 剪辑点 |
| `L` | 切换 A/B 循环 |
| `T` | 展开任务列表 |
| `F5` | 导出 A/B 片段 |
| `G` | 保存当前位置前 2 秒、后 3 秒的 MP4 |
| `↑` / `↓` | 上一个 / 下一个 |
| `←` / `→` | 在当前进度前 / 后随机跳转 |

## 手工验收边界

浏览器会主动阻止自动化授予本地目录读写权限。发布前应使用真实媒体目录手工验证一次：选择目录、重命名、截图、复制、A/B 导出、G 键快速片段，以及重新打开已授权目录。删除功能只用专门创建的可丢弃测试文件验收：取消后确认文件仍在；允许读写并确认后检查磁盘文件确实消失；拒绝权限后检查条目保留；分别删除非当前、当前和最后一项，并检查导出中的阻止提示。不要用真实资产测试永久删除。
